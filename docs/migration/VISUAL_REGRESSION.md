# 键盘、窄窗口与可访问性

把组件组合成页面后，需要检查用户能否真正完成操作。独立控件具备键盘行为，并不意味着应用中的标签、布局和保存反馈已经正确连接。

## 标签与焦点

每个输入应有可访问名称。可见标签通过 `htmlFor` 对应输入的 `id`；帮助信息通过 `aria-describedby` 关联。多个输入共同表示一个值时使用有名称的 group，同时给子输入各自命名。

只显示图标的 `ActionButton` 需要 `aria-label`。不要把改名、删除按钮嵌在另一个 button 中；使用组件提供的独立 actions 区域。

只用键盘尝试：Tab 能进入也能离开控件；Enter 和 Space 能激活按钮；选择控件能用方向键导航；Escape 能关闭当前浮层或取消尚未提交的编辑。等待状态不应让 Tab 被困在元素上。

## 对话框与浮层

对话框需要标题。直接组合 Dialog 部件时提供 `DialogTitle`；没有说明时按 Content 接口明确处理 `aria-describedby`。关闭后检查焦点是否回到合理的触发位置。

嵌套打开菜单、Popover 和 Dialog 时，先按 Escape 关闭最上层。长内容应能滚动到首尾，初始焦点不要落在屏幕外。Tooltip 适合补充说明，不能作为唯一可执行入口。

`asChild` 必须接收单个能转发 props/ref 的元素。自定义 React 组件需要把收到的事件、className、ARIA 和 ref 传到真实 DOM；Fragment 无法承担这个角色。

## 长内容和小窗口

把窗口缩窄，输入长名称，并切换明暗主题。确认页面没有意外水平滚动，标签不遮挡控件，按钮仍可点击，弹层顶部和底部都能访问。

在图形编辑器中，数值输入应提供拖动之外的精确操作方式。树和集合的动作按钮应保留清晰焦点；删除当前项后，焦点应移到可继续操作的位置。

## 保存反馈

尝试一次成功保存和一次失败保存。等待时应有状态反馈，失败后应能看见错误并重试；同一错误不应在字段和子编辑器重复朗读。

再尝试保存期间切换对象或接收外部数据。过期结果不应覆盖新对象的界面。组件只能处理显示和请求，服务器写入是否有效仍由应用判断。

## 只读与禁用

`readOnly` 表示可以读取但不能修改。某些复合组件仍允许打开预览、展开内容或翻页；不要把这些浏览行为当成保存。`disabled` 表示相关交互不可用，应用应提供必要原因。
